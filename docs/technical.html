Technical document

Aura technical

Does

  • watcher parses Claude Code and SDK-trace JSONL into a Parquet lake, oldest file first, flushing every 30 s.
  • redact.py scrubs secrets from payload before write; optional SHA-256 content hashing.
  • A dbt thread builds 32 models every 5 min into a work DB; cost is priced per model call.
  • Each successful run publishes a read-only DB read/v<stamp>; CURRENT switches atomically.
  • frontend serves 13 pages and 12 API handlers on 127.0.0.1:3000; /observability shows pipeline health.

Doesn't

  • Doesn't change or delete transcripts — logs mounted read-only (/logs/claude:ro).
  • Doesn't authenticate users or manage access — no login, no roles.
  • Doesn't fetch prices — only dbt/seeds/model_pricing.csv.
  • Doesn't use cron or Airflow — dbt runs on a watcher thread.
  • Doesn't deploy anywhere — CI checks only; Gemini/Codex adapters not built.

Limitations

  • Dashboard lags: one flush (30 s) + the wait for the next 5-min cycle + run and publish time.
  • Warm cycle time is not measured; the last full cold build took 1347 s (PASS=155, ERROR=0).
  • Incremental models rebuild only sessions with new lake rows.
  • dbt test failures don't block publish (dbt run, not dbt build).
  • One machine, one tenant (local); dbt pool 4000 MB inside a 5 GB container.

Top issues

  1. int_turns comment says sidechain turns get no prompt; code gives them the parent prompt — Confirmed
  2. int_entity_spend agent rows mix per-event spend with per-session tools and commits — Confirmed
  3. Footer price table is stale against the pricing seed — Confirmed
  4. aura.toml is read by no code — Confirmed
  5. CI builds no Docker image and does not run start.ps1 — Confirmed
  6. fact_prompts full refresh needs the full 4 GB pool — Confirmed
  7. Prompts of sessions without an app match keep app_id NULL — Not verified
  8. /observability layer ages not re-checked against current marts — Not verified

9.1 Delivery and dedup: at-least-once, key (tenant_id, uuid)

  • Parquet files are written first, the SQLite checkpoint commits after — watcher/src/aura_watcher/ingest.py:309-312.
  • A crash between the two re-reads the lines, so the lake can hold one uuid twice.
  • Newest ingested_at wins, then filename, then row number — dbt/models/staging/stg_lake_event_dups.sql:10-13.
  • stg_events anti-joins the losing copies — dbt/models/staging/stg_events.sql:29; compaction applies the same rule — watcher/src/aura_watcher/lake.py:236-242.
  • Claude rows: uuid = JSONL line uuid; SDK rows: <session>:<byte_offset> — watcher/src/aura_watcher/adapters/sdk_trace.py:109.
  • Message-level dedup (message_id) happens in dbt, not in the lake.

9.2 Cost formula with pricing SCD lookup

  • calculated_cost = sum(token bucket × per-Mtok rate) / 1,000,000; sdk_trace uses its reported cost.
INfact_model_calls.sql
CASE
  WHEN c.source = 'sdk_trace' THEN COALESCE(c.reported_cost_usd, 0)
  WHEN mp.model IS NULL THEN NULL
  ELSE ( input  × cost_input_per_mtok
       + output × cost_output_per_mtok
       + ephemeral_5m × cost_cache_write_5m_per_mtok
       + ephemeral_1h × cost_cache_write_1h_per_mtok
       + GREATEST(cache_creation − 5m − 1h, 0) × cost_cache_write_5m_per_mtok
       + cache_read × cost_cache_read_per_mtok ) / 1000000.0
END
INSCD join, fact_model_calls.sql
LEFT JOIN model_pricing mp
  ON c.model = mp.model
 AND (mp.tenant_id IS NULL OR mp.tenant_id = c.tenant_id)
 AND c.ts >= mp.valid_from
 AND c.ts <= COALESCE(CAST(mp.valid_to AS TIMESTAMP), '9999-12-31')
QUALIFY ROW_NUMBER() OVER (
  PARTITION BY c.tenant_id, c.message_id
  ORDER BY CASE WHEN mp.tenant_id IS NULL THEN 1 ELSE 0 END) = 1
